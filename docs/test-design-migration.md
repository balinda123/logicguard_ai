# 测试设计数据迁移

应用首次进入测试设计时，会把当前用户旧版 localStorage 中的用例、套件和报告整理成结构化记录，再交给 Rust 在 SQLite 事务中导入。

## 环境归类

- `localhost`、`127.0.0.1`、`::1` 归入“本地启动”（`local`）。
- 与管理员已配置共享测试地址同域名的记录归入“测试环境”（`test`）。
- 其他域名进入 `migration_quarantine`，不能用于执行，也不会创建第三种环境。

无需求来源的旧用例进入对应系统环境下的“历史导入设计单 · 模块名”，并生成明确标注为历史导入的占位需求版本，避免与新需求版本混用。

## 幂等与对账

每条源记录使用“用户 + 源键”去重。Rust 会对正式导入记录和隔离记录做数量对账；只有对账成功才写 SQLite `migration_markers` 并返回 `verified=true`。前端收到该结果后才写浏览器 marker。失败或中断时可再次执行，不会重复导入已记账记录。

旧读取器暂时保留用于迁移回查，正式测试设计页面不再从旧存储读取四阶段状态。该读取器是只读的一次性兼容层，计划在 `0.2.0` 删除；当前版本不会再向旧用例、套件或报告 localStorage/JSON 路径写入。
