# 需求文档建模页视觉统一设计

## 背景

`RequirementModeler` 当前使用独立的深色背景、青色主色和英文标题，与 LogicGuard AI 现有浅色工作台、紫色品牌色和中文界面明显割裂。本次仅统一视觉表现，不调整四步流程、字段、校验、抓取、AI 建模、草稿编辑或保存行为。

## 目标

- 复用全局 `surface`、`text`、`border`、`brand` 和状态色设计令牌。
- 使用与测试设计页一致的字号、控件高度、边框和按钮层级。
- 将四步导航改为顶部横向步骤条，让编辑区域保持居中和聚焦。
- 保持桌面和窄屏下内容可读、控件不重叠、操作区可换行。

## 页面结构

页面使用可滚动的浅色内容区，内部由三个无嵌套卡片层级的区域组成：

1. 标题栏：中文标题“需求文档建模”、简短说明和“返回测试设计”次要按钮。
2. 横向步骤条：展示输入网址、设置关键词、抓取网页、AI 建模四步。当前步骤使用紫色强调，已完成步骤使用成功色，未解锁步骤降低对比度并保持禁用。
3. 居中编辑区：根据当前步骤渲染原有表单。内容宽度受限，标题、说明、字段、反馈信息和操作按钮形成稳定的垂直层级。

草稿编辑区仍使用带边框的 `fieldset`，因为它是独立且可编辑的工具区域，不再叠加额外背景卡片。

## 组件与样式

- 页面背景使用 `bg-surface-1`，正文使用 `text-text-primary` 和 `text-text-secondary`。
- 输入框和文本域使用 `bg-surface-2`、`border-border`，焦点使用 `border-brand-500`。
- 主操作使用 `bg-brand-500`，返回和上一步使用浅色次要按钮。
- 错误、警告、成功和处理中反馈分别使用现有 `error`、`warning`、`success` 和 `brand` 语义色。
- 使用 Lucide 图标辅助返回、步骤状态和关键操作，不绘制自定义 SVG。
- 卡片圆角不超过现有页面惯例；固定格式控件使用稳定高度，避免状态变化导致布局跳动。

## 响应式行为

- 宽屏下步骤平均分布在一行，编辑区居中限宽。
- 窄屏下步骤条允许横向滚动并保持每步最小宽度。
- 标题栏和底部操作区允许换行，按钮文字保持完整且不遮挡相邻内容。
- 页面自身纵向滚动，避免被应用主内容区的固定高度裁切。

## 行为与数据流

本次不更改任何状态、事件或 API 调用。`step`、`highestStep`、`busy`、URL 校验、抓取失效、生成、保存及回调行为全部沿用现有实现。视觉状态仅由这些既有状态派生，不新增持久化数据。

## 错误与状态反馈

- URL 校验错误继续显示在字段附近。
- 抓取、生成和保存错误继续显示在当前编辑区底部。
- 处理中状态继续锁定步骤导航和相关操作。
- 已抓取内容因输入变化而失效时，继续显示警告并要求重新抓取。

## 验证

- 先补充会失败的渲染测试，约束中文标题、横向步骤导航和浅色设计令牌。
- 运行 `RequirementModeler` 组件测试，确认既有流程行为无回归。
- 运行项目 lint 和 build。
- 启动本地页面，在桌面和窄屏视口检查步骤条、表单、状态反馈、滚动和文字溢出。

## 非目标

- 不重构建模业务逻辑或 API。
- 不增删步骤、字段或操作。
- 不调整测试设计页及其他页面。
- 不引入新的依赖或全局设计令牌。
