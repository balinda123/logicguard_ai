# 面向新手的测试执行流程设计

## 目标

修复点击“开始回归”导致桌面应用进程退出的问题，恢复按需选择用例执行的能力，并让测试设计流程对没有自动化测试背景的用户也能直接理解。

## 用户流程

测试设计仍保留四个阶段，但用户可见名称调整为：

1. 需求内容
2. 生成用例
3. 检查用例
4. 执行测试

用户在“检查用例”中逐张检查卡片，可以编辑、删除或确认。已确认用例被编辑后自动退回“待确认”，必须再次确认才能执行。删除用例需要二次确认；删除后不再出现在当前设计和测试集合中。

“执行测试”只展示已确认用例。用户可以单选、多选、全选或清空选择，主按钮显示“执行所选用例（X 条）”。未选择用例时按钮不可用，系统不得默认执行全部用例。

## 用例卡片

检查和执行阶段复用同一种卡片视觉结构：

- 标题区展示用例名称、优先级、类型和确认状态。
- 内容区展示风险点、前置条件、测试数据、步骤和预期结果。
- 内容较长时卡片内部可折叠，不改为无边框长列表。
- 检查阶段提供编辑、删除、确认操作。
- 执行阶段提供选择框，不提供编辑入口，避免执行范围变化不明确。

编辑采用卡片内表单或同层弹窗，至少支持名称、风险点、前置条件、步骤和预期结果。保存后持久化完整 payload，并将状态设为 `draft`。

删除采用软删除：将状态设为 `archived`，保留审计数据，但默认列表、测试集合和执行范围均排除归档用例。

## 测试集合与执行范围

“回归套件”统一显示为“测试集合”。测试集合是一个可保存的命名用例集合：

- 用户可以从已确认用例中勾选若干条，保存为测试集合。
- 用户可以选择已有测试集合并载入其用例选择。
- 用户也可以不保存集合，直接执行当前临时选择。
- 执行任务的快照只包含本次明确选中的用例 ID 和生成的命令，不读取选择之后发生的修改。

第一阶段复用现有 `regression_configs` 存储当前设计的集合配置；若后端结构只能保存单个配置，则先支持一个默认命名集合和临时选择，不引入与本次目标无关的复杂集合管理页面。

## 崩溃处理

点击执行的调用链划分为四个可观察阶段：

1. 校验环境地址和所选用例。
2. 保存测试集合或临时执行范围。
3. 创建后台执行任务。
4. 后台进程预检、浏览器锁定和执行。

前端捕获每个阶段的错误，在当前页面显示可操作的中文提示，并始终清除按钮的忙碌状态。Rust 后台不得在 Tauri/Windows 回调边界 panic；所有输入校验、浏览器查找、窗口枚举、工作进程启动和状态切换错误必须转换为任务的“无法继续”状态或 Tauri 命令错误。

修复前先用当前崩溃栈、日志和最小回归测试确认根因。若根因位于 Windows 窗口枚举回调，则回调只采集原始窗口句柄，不执行可能 panic 的业务逻辑，并在回调外完成校验；若根因在其他边界，则按实际证据修复，不用吞 panic 代替根因处理。

## 全局小白文案

用户界面采用业务动作名称，内部类型、数据库列名、开发日志和协议字段保持不变。

| 当前名称 | 用户可见名称 |
| --- | --- |
| 测试设计 | 设计测试 |
| 需求来源 | 需求内容 |
| 检查确认 | 检查用例 |
| 回归执行 / 开始回归 | 执行测试 / 执行所选用例 |
| 回归套件 | 测试集合 |
| 执行中心 | 测试运行 |
| 快照 | 本次执行信息 |
| 阻断 / execution blocked | 无法继续 |
| 人工交接 | 等待人工操作 |
| 终止 | 停止测试 |

技术名称可放在开发日志或帮助提示中，不作为主要按钮和标题。错误提示必须说明发生在哪一步、用户现在可以做什么，避免只显示内部错误码。

## 数据与接口

新增或扩展测试设计接口：

- 更新用例 payload，并把状态退回 `draft`。
- 将用例状态更新为 `archived`，列表默认过滤归档项。
- 保存并读取当前设计的测试集合名称及用例 ID。
- 创建执行任务时只使用前端传入并经后端校验的已确认用例 ID。

所有接口继续按当前用户、系统、环境和设计 ID 校验归属，禁止跨设计修改或执行用例。

## 测试要求

- 前端测试覆盖卡片显示、编辑后退回待确认、删除确认、归档过滤、单选、多选、全选、载入测试集合及只执行所选用例。
- 前端测试覆盖保存配置或创建执行任务失败时显示中文错误且应用保持可操作。
- Rust 测试覆盖 payload 更新、软删除、集合用例归属校验、只允许已确认用例进入执行范围。
- 为实际崩溃根因增加 Windows 或可抽象边界的回归测试，确保错误返回而不是进程 abort。
- 完成后运行相关 Vitest、Rust 定向测试、TypeScript 检查、前端生产构建和文档一致性检查。

## 非目标

- 不重命名内部 Rust/TypeScript 类型、数据库表或历史迁移字段。
- 不在本次重做执行中心和报告的数据模型。
- 不删除历史审核记录或归档用例。
- 不默认执行全部已确认用例。
