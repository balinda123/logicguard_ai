# 多账号状态化测试与问题闭环设计

> 状态：设计已确认，尚未实现。
>
> 目标系统：试用期管理及转正审批系统。首版围绕该系统交付，底层模型保留扩展到其他审批系统的能力。

## 1. 目标与边界

LogicGuard AI 当前能够抓取需求、生成测试用例、回放单账号脚本并保存运行报告。本设计将其扩展为可验证跨角色业务状态的测试工作台，同时保留单角色功能、边界和权限测试。

首版目标：

- 从 PRD 生成可审阅的功能规则用例与流程场景。
- 使用员工、直属上级、HRBP 等关联测试账号，在同一业务单据上完成状态化测试。
- 支持普通账号自动切换；遇到 SSO、验证码或 OTP 时暂停人工接管，并从检查点继续。
- 仅在业务断言失败时保存截图和证据，形成测试人员可编辑的待确认问题草稿。
- 将已确认的问题以表格清单管理，并导出 Excel 或 CSV 交付开发。

首版不包含：

- 飞书多维表格或其他外部缺陷平台同步。
- PeopleSoft / HR 便捷工作台内部审批结果跟踪。
- 将密码、OTP 或原始敏感测试数据写入 localStorage、SQLite、截图文本、日志、导出文件或 LLM 请求。
- 任意目标系统的零配置自动化；首版仅预置试用期转正流程。

## 2. 用例分层

需求建模的输出分为两类，它们进入同一场景库和回归套件，但对账号和状态的要求不同。

| 类型 | 账号需求 | 示例 |
| --- | --- | --- |
| 单角色功能与边界 | 仅绑定一个角色账号 | 员工目标内容 100 字允许提交、101 字提示错误、必填校验、权重合计、草稿保存、重复提交 |
| 单角色权限 | 操作账号；必要时增加只读验证账号 | 员工不能访问 HRBP 管理页；上级不能评价非下属员工 |
| 跨角色主流程 | 绑定同一组织关系下的员工、上级和 HRBP | 员工提交目标 -> 上级确认 -> HRBP 开启评价 -> 员工自评 -> 上级评价 |
| 跨角色异常分支 | 绑定该分支所需账号 | 上级退回目标、HRBP 终止转正、人员离职、上级变化 |

AI 只负责从 PRD 归纳场景草稿、字段规则和状态转换。测试人员必须审阅并确认场景；未确认场景不可执行。

## 3. 核心对象

### 3.1 测试账号

测试账号描述一个可用于目标环境登录的身份：

- 显示名称、环境、业务角色、脱敏账号名和启用状态。
- 登录模式：自动登录、SSO 人工接管、OTP 人工接管。
- 凭据引用：仅保存系统凭据库中的 service/account 标识，不保存密码明文。
- 登录验证规则：用于确认当前浏览器已进入指定账号和角色的页面特征。

仅管理员可新建、修改、禁用或测试账号；普通测试人员可以在有权限的范围内选择账号运行场景，不能查看密码。

### 3.2 账号组合与测试数据

账号组合将员工、直属上级、HRBP 等角色绑定为一组关联测试数据，并记录环境与组织关系校验信息。跨角色场景必须引用账号组合；单角色场景只引用所需账号。

账号组合包含明确的数据准备策略：创建新单据、复用已准备单据或人工准备。执行器不会静默复用上一批次的残留状态。

### 3.3 测试场景

场景替代当前仅有步骤文本的执行模型，至少包含：

- 来源需求和关联验收条款。
- 场景类型、优先级、前置状态、数据准备策略和所需角色。
- 有序步骤。每步包含执行角色、业务动作、预期页面结果、预期业务状态、是否为人工接管点。
- 单据关联规则与关键状态检查点。
- 状态：草稿、已确认、已归档。

### 3.4 执行批次与检查点

执行批次是场景的一次运行，保存账号和测试数据的快照，避免后续配置变更改写历史。状态为待执行、运行中、等待人工接管、执行异常、业务失败、已通过或已完成。

每个完成步骤都保存检查点：当前角色、登录验证结果、单据标识、业务状态、语义化动作摘要和时间。批次可在人工接管后或短暂中断后从最后一个成功检查点继续。

运行期间锁定关联账号和账号组合，防止并发批次污染同一条业务数据；结束、终止或超时后释放锁。

### 3.5 证据与问题草稿

正常步骤只保存文本化执行记录，不截图。业务断言失败时保存当前页面截图、脱敏页面文本、预期结果、实际结果、当前角色、状态、单据标识和执行日志。

业务失败自动生成问题草稿。浏览器连接失败、元素无法定位、未完成验证码、网络中断和前置状态不成立属于执行异常，不自动归因给开发，也不生成问题草稿。

测试人员可以编辑问题草稿的描述、优先级、复现路径和补充证据，再决定确认或标记为非问题。AI 原因分析只在测试人员明确请求时发送失败截图和脱敏上下文。

## 4. 页面设计

### 4.1 首页：测试工作台

首页以启动和继续工作为主，不使用大面积统计卡：

- 顶部主操作：导入需求、创建场景、开始执行、查看问题；根据当前数据前置条件启用。
- 主区域展示当前或最近一个未完成批次，包括当前角色、最新语义化步骤、人工接管状态和继续执行入口。
- 待处理区域展示等待人工登录、待确认问题和待验收问题。
- 最近结果以紧凑列表显示最近批次和最近确认的问题，统计仅作为列表辅助信息。

### 4.2 测试设计与场景库

保留现有需求 URL/文本抓取和 AI 建模能力。生成后增加规则覆盖清单，明确区分功能规则、边界、权限、单角色与跨角色流程。现有“测试用例”页面升级为“测试场景”，支持按上述类型筛选，场景详情展示前置状态、所需角色、步骤、测试数据和断言。

回归套件保留，并允许混合收录员工边界用例与跨角色流程场景。

### 4.3 测试账号与账号组合

在系统设置中新增管理员入口，用表格管理测试账号和账号组合。账号编辑页只展示密码是否已配置、登录方式和测试连接结果，不回显密码。账号组合页面校验员工、上级、HRBP 的组织关系与目标环境。

### 4.4 执行中心

新增执行中心，承接当前 `TaskExecutionConsole` 的实时事件能力。列表展示执行批次；详情按时间显示：时间、当前角色、业务状态、浏览器动作、预期断言、实际结果和证据。

原始浏览器日志默认折叠，首先展示测试人员可读的语义化步骤。SSO/OTP 时显示人工接管说明和继续按钮。正常步骤不产生截图；失败步骤在详情和对应问题草稿中显示唯一的自动截图。

### 4.5 问题清单与执行记录

现有报告页按职责拆分为：

- 执行记录：保存完整批次诊断、检查点、运行状态和文本日志。
- 问题清单：以紧凑表格展示已确认问题，字段为问题描述、需求/场景、测试角色、预期结果、实际结果、截图、优先级、状态、执行日期和执行批次。

问题详情在侧边抽屉查看复现步骤、失败截图和日志。问题生命周期固定为：待确认 -> 待修复 -> 待验收 -> 已关闭；测试人员可在待确认阶段标记为非问题。仅待修复、待验收和已关闭的问题可导出 Excel/CSV。

## 5. 执行协议

跨角色执行遵循以下顺序：

1. 校验目标环境、账号可用性、账号组合关系和初始业务状态。
2. 登录第一个角色并执行步骤，保存单据标识与状态检查点。
3. 需要切换角色时退出并清理会话，登录下一个账号，再验证当前账号和角色。
4. 对 SSO/OTP 停止自动动作，等待测试人员完成登录并确认；随后从检查点续跑。
5. 每步验证页面结果和业务状态。业务断言失败即停止当前场景、保存失败证据并创建待确认问题草稿。
6. 执行结束后汇总文本记录；无业务失败则标记为已通过，执行阻塞则标记为执行异常。

首版沿用单受控浏览器，角色按顺序切换。并行多浏览器上下文、并发账号组合和跨系统流程编排不在首版范围内。

## 6. 安全与隐私

- 测试账号密码存放到 Windows Credential Manager 或 macOS Keychain，关联当前 LogicGuard 用户与测试账号 ID。
- 前端、localStorage、SQLite、报告、导出、LLM 提示词和截图旁注仅保留脱敏账号标识与凭据引用。
- 密码字段、OTP 输入、常见人事个人信息和用户配置的敏感字段必须在事件文本与导出内容中脱敏。
- 失败截图仅保存在本机应用数据目录，并在问题删除或用户清理记录时一并清理；首版不自动上传。
- 模型分析是显式操作，默认使用严格脱敏后的失败文本和截图；用户可取消，不影响人工确认流程。

## 7. 验收与验证

功能验收：

- 员工账号能独立执行目标字段 100 字、101 字、空值、权重合计与重复提交等边界场景。
- 关联员工、上级和 HRBP 账号组合能跑通试用期目标、开启评价、自评和上级评价的主状态链。
- SSO/OTP 人工接管可暂停、验证登录身份并从同一检查点继续。
- 业务断言失败只保存失败页面截图并生成待确认问题草稿；执行异常不生成开发问题。
- 已确认问题能以表格管理，并导出 Excel/CSV，且不含密码、OTP 或未脱敏敏感数据。

实现验证：

- 单元测试：状态转换验证、角色账号选择、凭据引用隔离、失败分类、问题生命周期和导出字段过滤。
- 组件测试：场景确认门禁、人工接管提示、问题确认和非问题流程。
- 集成测试：使用模拟目标页面跑单角色边界和多角色状态链；使用真实受控浏览器验证登录切换和检查点恢复。
- 回归检查：现有需求建模、单账号脚本执行、报告读取和用户隔离保持可用。

## 8. 实施影响

实施会新增测试账号、场景、执行批次、证据与问题草稿的数据模型和本地持久化，并拆分当前用例执行与报告页面职责。新增 Tauri 命令、凭据写入路径、截图文件管理和导出功能时，必须同步更新 README、开发文档、部署说明、sidecar 协议说明和测试覆盖说明；在代码实现前，本设计不改变当前产品行为。
