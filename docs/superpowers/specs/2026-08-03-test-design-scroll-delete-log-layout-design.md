# 测试设计滚动、删除与日志布局设计

## 目标

让测试设计页面在用例内容较多时仍可快速操作，并确保检查阶段删除的流程不会残留到回归阶段或回归套件中。

## 页面布局

- 左侧步骤导航保持在视口内，不随右侧长内容滚走。
- 右侧步骤工作区使用视口约束高度和内部纵向滚动，不再依赖整个页面滚动查看长内容。
- “回归执行”保留顶部套件选择区；其下在宽屏分成主区和日志侧栏。
- 主区展示已确认用例并独立滚动；右侧日志容器始终可见，显示空状态、运行状态和最近执行日志，并在内容增长时内部滚动。
- 小屏幕改为单列：套件选择、日志容器、用例列表依次显示，日志仍有固定最大高度和内部滚动。

## 删除流程

- “检查确认”的每张用例卡增加带垃圾桶图标的删除按钮，草稿和已确认用例都可删除。
- 点击后使用确认对话框显示用例标题；取消不改变任何状态。
- 确认后从当前 `cases` 删除并调用 `saveTestCases` 持久化。
- 同时从每个包含该用例 ID 的回归套件 `caseIds` 中移除，并通过现有 `upsertSuite` 持久化更新后的套件。
- “回归执行”直接使用更新后的 `confirmedCases` 和 `suites`，因此不再显示已删除用例，也不会继续执行套件中的残留 ID。
- 删除最后一个已确认用例后，第 4 步重新锁定；当前操作发生在第 3 步，不需要强制跳转。

## 日志行为

- 日志侧栏即使尚未执行也显示，避免用户不知道日志位置。
- 执行时沿用现有 `runLog`，每次追加立即刷新侧栏。
- 日志容器使用等宽字体并保留最近日志；内容超出高度时仅滚动日志区域。
- 本次不改变报告内容、日志脱敏、执行协议或截图策略。

## 测试

- 删除确认后，用例从检查确认页消失，`saveTestCases` 收到删除后的集合。
- 被删除用例从所有关联套件移除，进入第 4 步后不可见。
- 取消删除时不调用持久化接口。
- 删除最后一个已确认用例后，第 4 步锁定。
- 回归执行页面存在独立日志区域及空状态，日志不再渲染在用例列表之后。
- 构建检查确保响应式网格和滚动容器没有类型错误。
