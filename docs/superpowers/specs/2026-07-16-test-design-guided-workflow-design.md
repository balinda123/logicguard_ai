# 测试设计分步向导改版设计

## 目标

将“测试设计”和“从需求文档智能提取生成自动化测试用例”改造成面向新手的顺序式向导，修复建模页返回旧“场景模板列表”的错误，并删除已经没有可见入口的旧模板列表与配置运行界面。

## 已确认的问题

1. `TestCases` 通过 `App.tsx` 的 `templateModeler` 标签打开 `Templates` 的生成视图，但 `Templates` 内部的返回按钮固定把 `currentView` 切换为 `list`。因此，从测试设计进入建模页后会错误返回旧模板列表，而不是返回测试设计。
2. 旧模板列表没有侧边栏或其他可见入口，只有 `App.tsx` 中遗留的 `templates` 分支。它附带的搜索、分类、模板卡片、参数配置与旧运行界面已经脱离当前测试设计主流程。
3. 需求文档抓取区先展示关键词，再展示抓取按钮，没有明确要求目标网址，也没有把“打开网址”和“抓取内容”串成一个可理解的动作。
4. 当前测试设计把需求、模板、套件和生成按钮同时铺在页面上。顶部阶段卡片只用于展示，不能表达当前步骤、完成状态、解锁条件或返回操作。

## 范围

### 包含

- 修复需求建模页的返回来源。
- 将需求文档抓取改为严格有序的四步子流程。
- 将测试设计改为可前进、可返回、带解锁条件的四步主向导。
- 保存新模板后返回测试设计并自动选中新模板。
- 删除无入口的旧模板列表、模板配置和旧模板运行界面。
- 保留模板数据结构、本地存储、默认模板和基于模板生成测试用例的能力。
- 为公开 UI 行为增加自动化测试并同步用户与开发文档。

### 不包含

- 修改模板、测试用例或回归套件的数据格式。
- 修改 LLM 生成提示词的业务策略。
- 修改 CDP 端口、浏览器配置或鉴权流程。
- 新增独立模板管理入口。

## 信息架构

### 测试设计主向导

主向导包含四个严格按顺序解锁的阶段：

1. **需求来源**：填写模块名称与需求正文，也可打开需求文档建模向导。
2. **生成用例**：选择“直接从需求生成”或“基于场景模板生成”。场景模板是生成方式，不再作为所有用户都必须经过的独立阶段。
3. **检查确认**：查看 AI 草稿，逐条人工确认测试用例。
4. **回归执行**：选择或新建回归套件，将已确认用例加入套件并执行。

页面使用左侧纵向步骤轨道和右侧单一工作区。只有当前阶段使用主视觉强调；已完成阶段显示完成状态；未解锁阶段降低强调并禁止进入。底部固定提供与当前阶段匹配的“上一步”和主操作按钮。

用户可以点击已完成阶段或“上一步”返回。返回不会清空模块名称、需求正文、生成方式、已生成用例、模板选择或套件选择。修改上游输入时，仅将依赖旧输入的下游完成标记重置，并明确提示用户需要重新生成；不会静默沿用过期结果。

### 需求文档建模子向导

从测试设计第一阶段打开全屏子向导，包含以下顺序：

1. **输入需求文档网址**：必填，只接受 `http://` 或 `https://` URL。
2. **输入关键词过滤**：可选，用于缩小抓取范围。
3. **打开并抓取网页**：按钮只在 URL 合法且当前未执行时启用。点击后自动导航托管 Chrome，等待导航完成，再抓取该页面正文并应用关键词过滤。
4. **检查正文并 AI 建模**：抓取结果写入可编辑正文框。正文非空时才允许 AI 解析。用户可修正文档内容后生成模板草稿并保存。

子向导的“上一步”保留 URL、关键词、抓取正文和生成草稿。修改 URL 或关键词后，已有抓取结果标记为过期，并要求重新抓取后才能继续建模。

顶部返回、文字返回和取消操作统一回到测试设计的原阶段，不进入旧模板列表。保存模板后回到测试设计第二阶段，并自动选中新模板。

## 组件边界

- `TestCases` 负责测试设计主向导、业务数据和当前步骤状态。
- 新的需求文档建模组件只负责 URL、关键词、页面抓取、正文编辑、模板草稿生成与保存，通过 `onCancel` 和 `onSaved(template)` 与 `TestCases` 通信。
- 抽取纯向导状态规则，用独立函数或 reducer 表达步骤解锁、前进、返回和上游变更后的失效逻辑，便于单元测试。
- `App.tsx` 只保留公开导航标签，不再维护 `templates`、`templateModeler` 和 `testcases` 等重复或隐藏分支。
- `templateGenerator`、`defaultTemplates` 和模板类型继续作为测试设计的可复用数据层。

## 状态与数据流

1. `TestCases` 加载测试用例、套件、自定义模板和默认模板。
2. 用户在第一阶段填写需求，或打开建模子向导。
3. 子向导依次调用浏览器导航、页面正文抓取和模板生成 API。
4. 子向导保存模板后，把完整 `ScenarioTemplate` 返回给 `TestCases`。
5. `TestCases` 重新合并自定义模板与默认模板，选中新模板并进入第二阶段。
6. 用户选择直接生成或模板生成，得到去重后的草稿用例。
7. 草稿经人工确认后才能加入套件和执行。

主向导保持挂载，打开子向导时不销毁已有测试设计状态，因此取消或返回后无需依赖全局标签恢复表单。

## 校验与错误处理

- 空 URL 或非 HTTP(S) URL：在输入框下显示明确错误，禁用抓取按钮。
- 浏览器导航失败：停留在网址步骤并显示错误；保留 URL 和关键词。
- 页面抓取失败或结果为空：停留在抓取步骤并提供重试；不解锁 AI 建模。
- 关键词没有匹配内容：显示未匹配提示，允许用户返回修改关键词或清空关键词后重试。
- AI 生成失败：保留抓取正文并提供重试，不要求再次抓取。
- 保存失败：保留生成草稿并显示错误，不返回主向导。
- 执行中的按钮显示忙碌状态并防止重复提交。

## 删除策略

删除旧模板列表专属的以下内容：

- `Templates` 的 `list` / `configure` 视图状态和渲染分支。
- 模板分类、搜索和卡片列表。
- 参数集配置抽屉、旧模板运行控制台及其页面局部状态与处理函数。
- 旧列表的编辑、删除和返回逻辑。
- `App.tsx` 中无入口的 `templates`、`templateModeler` 和重复 `testcases` 分支。

不删除仍被当前流程使用的模板加载、保存、默认模板合并、参数集数据读取或基于模板生成测试用例逻辑。

## 测试策略

增加前端测试基础设施，优先测试用户可观察行为：

- 从测试设计打开建模页，取消或返回后仍回到测试设计且保留原输入。
- 主向导不能越过未满足条件的阶段，完成后可前进和返回。
- 修改上游输入会使相关下游结果过期。
- URL 格式不合法时不能抓取。
- 合法 URL 会先调用浏览器导航，再调用页面抓取，并传入关键词。
- 抓取失败、空结果和无关键词匹配时不会解锁 AI 建模。
- 保存模板后返回第二阶段并自动选中新模板。
- 直接生成、模板生成、人工确认、加入套件和执行的现有行为不回退。

验证命令至少包括定向测试、完整前端测试、ESLint 和生产构建。
