# 自动登录元素识别设计

## 目标

自动登录账号只要求填写显示名、角色、登录方式、登录地址和凭据。页面、用户名、密码、提交按钮及成功标记选择器保留为可选高级配置，不再阻塞保存。

## 交互设计

- 自动登录表单默认展示登录地址、账号用户名和账号密码。
- “高级设置（可选）”默认折叠，展开后才能看到五个选择器。
- 手工选择器存在时优先使用；缺失或已失效时继续自动识别。
- 校验或保存失败在编辑卡片内部显示醒目的红色提示，同时标红对应字段、滚动并聚焦第一个错误字段。
- 保存失败保留输入；保存成功刷新列表并关闭编辑卡片。

## 登录定位流程

1. Sidecar 打开登录地址并等待可选页面标记。
2. 对用户名、密码和提交按钮依次尝试手工选择器。
3. 手工选择器不可用时，尝试常见语义属性、输入类型、名称、自动填充属性和按钮文本等本地规则。
4. 本地规则仍无法唯一定位时，使用当前已配置模型调用 Stagehand `observe` 获取候选选择器。
5. Sidecar 使用 Playwright 在本地填入凭据并点击提交；AI 只接收元素识别指令，不接收用户名、密码或包含凭据的指令。

## 接口变化

- `BrowserLoginPayload` 的用户名、密码、提交按钮选择器改为可选。
- `browser_login_test_account` 接收当前 `LlmConfig`，仅用于给 Sidecar 注入 Stagehand 模型配置。
- 前端 `loginTestAccount` 传递 `getLlmConfig()`；账号凭据仍只由 Rust 从系统凭据库读取。

## 失败处理

- 缺少基础账号信息时不调用保存接口，并在卡片中明确列出缺失项。
- 本地和 AI 均不能定位时返回不包含凭据的统一登录失败错误。
- 没有可用模型配置时仍可使用手工选择器和本地规则；AI 兜底失败不会泄露凭据。

## 验证

- 前端测试覆盖高级设置默认折叠、不填选择器可保存、字段错误可见并聚焦。
- Sidecar 单元测试覆盖可选选择器解析、本地规则、手工选择器优先和 AI 兜底。
- 桥接测试覆盖模型配置传递且调用参数不含账号凭据。
- Rust 编译检查覆盖新的可选字段和命令参数。
