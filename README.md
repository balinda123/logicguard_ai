# 测试小助手

> 当前执行架构：设计测试按“系统 + 环境”隔离，测试运行、报告和问题跟踪跨系统统一展示。所有生产浏览器步骤由 Rust 持久运行管理器调度到 Stagehand worker；前端直连 Playwright/CDP 和旧脚本执行器已删除。运行、事件和报告来自 SQLite，API Key 与测试账号凭据保存在操作系统凭据库。执行前检查会启动或恢复本应用专属受控浏览器，并把执行计划中已校验的域名白名单传给 worker；测试运行页按北京时间展示更新时间，右侧深色日志区实时恢复并滚动显示持久化步骤事件。

架构升级、旧数据迁移、回滚与清理规则见 [system-scoped-stagehand-v1](./docs/migrations/system-scoped-stagehand-v1.md)。

测试小助手是一个桌面自动化测试工具。用户从系统级设计测试中勾选用例并开始测试，Rust 在后台调度本机 Stagehand worker 连接专用 Chrome CDP 执行。

## 当前能力

> 自动执行的浏览器输入保护当前仅支持 Windows。必须由应用“一键启动受控浏览器”创建专用 Chrome Profile 并登记进程 PID；外部 CDP 浏览器、PID/顶层窗口校验失败，或 macOS/Linux 上尝试自动执行时，运行会以 `BROWSER_INTERACTION_LOCK_UNAVAILABLE` 进入 blocked，不会下发页面动作。Windows 保护只禁用该专用浏览器的顶层窗口输入，不安装全局键鼠 hook；Stagehand/CDP 后台通信仍可继续。

- 多账号流程测试：在“设计测试 → 生成用例”中按当前系统和环境自由定义业务角色并添加多个账号；AI 只能从已配置的非敏感账号元数据中选择每一步的执行者，不预设员工、上级或 HRBP
- 安全执行中心：自动账号在单一受控浏览器中按角色切换；SSO/验证码场景停在人工交接后继续；仅业务断言失败保存截图
- 全局运行控制：切换左侧页面不会停止后台任务；顶部持续显示系统、环境、套件、进度和浏览器受控状态，并按运行状态提供查看、暂停、继续和终止。暂停或等待人工操作时，当前步骤停止旋转并显示醒目的暂停提示，浏览器解除控制；进入暂停、人工接管或停止状态时，桌面系统会弹出原生通知。受控网页显示闪烁边框和“请勿点击”提示，只在真实点击或填写位置显示短暂的圆点波纹，人工输入仍由 Windows 浏览器交互锁阻止；运行页以步骤时间线和中文执行动态为主，原始事件收在可展开的“技术详情”中。已结束的运行记录可在日志面板中确认后删除，执行中的任务必须先停止
- 应用登录后会自动并行检查模型、浏览器和 Sidecar 连接，检查完成前显示“检测中”，无需先点击顶部刷新按钮；刷新按钮仍可用于配置变化后的手动复检
- 全局报告与问题：任务控制台、执行中心、测试报告和问题跟踪可按系统、环境、状态和时间筛选；只有 `business_failed` 形成缺陷，`blocked/cancelled/interrupted` 仅作为运行诊断
- 问题跟踪：`business_failed` 与待确认问题单在同一事务中写入；确认后进入修复/验证生命周期，支持筛选并导出 Excel 或 CSV

- Stagehand 是唯一生产浏览器执行路径；确定性 locator 与受限语义 Agent 共用同一持久 worker
- “设计测试”：先选择系统和本地/测试环境并输入设计名称，再从设计列表进入“需求来源 → 生成用例 → 检查用例 → 执行测试”；未填写名称时点击“新建设计”会弹出全局提示并聚焦名称输入框。顶部步骤导航会随内容滚动保持可见，并按持久化进度恢复上次位置，全部用例确认后默认进入“执行测试”，设计列表也提供执行快捷入口。需求来源既可手工填写，也可通过“输入网址 → 设置关键词 → 抓取网页 → AI 整理需求”提取网页正文；抓取会直接打开本次输入的网址，不受浏览器中其他系统残留页面影响，实际跨域重定向仍会被安全拦截。多个需求关键词使用中文分号 `；` 分隔，或一行填写一个；默认先按 DOM 原文零 Token 匹配，在线文档画布的 DOM 不可读或标题未命中时自动改用同样不消耗 Token 的页面可访问性文本，命中目录标题后会逐章跳转并合并正文。部分未匹配项会单独提示，全部未匹配时回退完整可读正文供用户检查。仍无法确定性识别时，可主动开启默认关闭的“AI 语义匹配”：当前页面可见内容或截图会发送到当前模型并消耗 Token，只读 Agent 仅可读取、滚动和提取，不可点击、输入、导航或搜索。第四步只整理角色、状态流转、校验规则、边界值和覆盖场景，不生成页面操作步骤；四阶段数据统一持久化到同一设计
- 生成用例期间会展示“读取需求与账号 → AI 规划并生成 → 检查结果 → 保存用例”的真实工作流和已用时间。当前模型接口一次返回完整 JSON，因此等待模型时不会伪造尚未返回的单条用例；模型返回后立即校验、保存并进入逐条检查页面，失败会停留在对应阶段并显示原因
- 检查用例：用例保持卡片展示；已确认用例仍可编辑和删除，编辑后会回到待确认，删除采用软删除并同步移出测试集合
- 执行测试：从已确认用例中勾选本次范围，也可命名并保存为测试集合。“本次执行账号”只读取当前系统已配置的动态角色；所选用例用到某角色时必须明确选择该角色账号才能开始，没有角色的用例不要求账号映射。账号未选完整时，点击执行会显示全局警告、定位账号区域并高亮第一个缺失项。替换只影响本次运行，不修改用例、不重新调用 AI，也不消耗 Token。点击执行后，按钮区域会持续显示账号检查、任务创建或启动失败信息。集合按“账号 + 操作 + 预期结果 + 断言 + 测试数据”精确去重；同一用例内连续且同账号的步骤合并为一轮有界 Agent，角色变化仍是强制账号交接点，跨用例会重新打开环境入口，避免沿用偶然页面状态。简单且有明确 DOM/URL 证据的动作优先使用快速语义操作并执行无模型断言，失败才升级为 Agent。执行器先用密码框、账号标识或登录成功标识判断登录状态；自动登录页有多个普通入口时按当前系统名称选择“登录目标系统”，并排除 SSO、扫码和验证码入口。环境入口导航允许 302 落到已配置的可信登录域名，随后立即停止业务动作并进入人工接管；未配置时只显示被拦截的 origin，不记录路径或查询参数。DOM 已明确时不再调用 AI，证据不足才进入人工接管。账号 ID 变化时强制重新登录，所有页面和 AI 动作仍受当前环境域名白名单约束。新任务会把当前模型、推理服务地址等非敏感配置固化到运行快照；API Key 仍只从系统凭据库临时读取
- 场景模板、执行日志、自愈记录和测试报告
- 报告包含管理摘要、风险等级、发版建议、失败复现路径和技术日志
- 本地管理员/普通用户登录
- 管理员用户列表、创建用户、禁用用户和重置密码
- 系统设置页展示本机数据存储位置，并可打开应用数据目录；管理员可在“被测系统与环境”列表中新增、编辑、启停和删除未被测试设计使用的系统/环境。列表默认展开第一个系统，也可点击“几个环境”查看或收起环境配置；登录地址和可信登录域名在具体环境的编辑区维护
- 按用户隔离模型配置、模板、测试设计和运行报告
- API Key 保存到 Windows Credential Manager 或 macOS Keychain
- 模型提供商提供 DeepSeek、OpenAI、通义千问、Kimi、智谱、豆包、Gemini、Ollama 和自定义 OpenAI Compatible 预设
- 数据安全模式默认“严格脱敏”，发送给模型前会遮蔽手机号、身份证、邮箱、银行卡、薪资、部门等敏感值
- 安装包内置 Node.js 22 和 sidecar，运行端无需安装 Node.js
- Windows x64 NSIS 安装包
- macOS Apple Silicon `.app` / `.dmg` 构建支持（当前未签名）

当前版本不依赖 PocketBase、Tailscale、Ollama 或其他自建服务。每个用户配置自己的 Gemini 或 OpenAI Compatible API Key。

## 架构

```text
React / Tauri WebView
        │ invoke / event
        ▼
Rust 后端
  ├─ 本地登录：SQLite + Argon2id
  ├─ 系统凭据：Credential Manager / Keychain
  ├─ 云模型请求
  ├─ 用户报告存储
  └─ sidecar 进程管理
        │ JSON Lines + CDP
        ▼
内置 Node.js 22 + Playwright + Stagehand
        │
        ▼
Chrome / Edge
```

## 安装版首次使用

1. 安装并启动测试小助手。
2. 首次启动创建本机管理员账号。
3. 管理员可在“系统设置”中创建普通用户。
4. 当前用户配置模型 Provider、Model、Base URL（如需要）和自己的 API Key。
5. 点击“测试并保存配置”。
6. 设置 CDP 端口并点击“一键启动受控浏览器”。
7. 在浏览器中完成目标系统登录，然后开始自动化任务。
8. 进入“设计测试”，选择系统和环境；管理员也可点击系统选择器旁的 `+` 快速创建。创建或编辑环境时统一填写系统入口、登录地址和可信登录域名，该环境下的测试账号不再重复填写这些地址。新建设计后，在“需求来源”中手工填写，或点击“从网页抓取需求”完成网址、关键词、网页抓取和 AI 整理需求四步，使用整理结果后保存新版本。随后在“生成用例”中按目标系统实际情况填写任意业务角色和测试账号；账号 ID、角色名称、显示名和登录方式会提供给 AI，真实凭据不会发送给模型。具体页面操作步骤只在生成用例时产生。在最后一步勾选本次要运行的用例，可直接执行或保存为测试集合。详细步骤见 [OpenMontage使用指南.md](./OpenMontage使用指南.md)。

API Key 和测试账号真实凭据不写入 localStorage、SQLite、日志、报告或导出文件；它们仅保存在 Windows Credential Manager 或 macOS Keychain。登录是本机应用级隔离，不用于抵御拥有操作系统管理员权限的攻击者。
可信登录域名在“系统设置 → 被测系统与环境”的环境创建或编辑区统一维护，只需填写域名（如 `sso.oa.wanmei.net`），多个域名一行一个；粘贴完整 SSO 地址时编辑器会去掉协议、路径和参数，保存时转为标准 HTTP(S) origin（未写协议时默认 HTTPS）供该环境下全部账号共用。
自动执行期间，受控页面顶部和标题显示“自动化执行中”以及 system/environment/run/step 标识；标识协议不接受密码、令牌、OTP、secret、credential 或对应占位符。测试账号凭据只由 Rust 从系统凭据库短暂读取，经独立登录子进程传递并在使用后 zeroize，不进入普通 Stagehand 请求。
人事测试环境默认按敏感数据处理；严格脱敏只能降低传给模型的文本风险，仍建议测试环境使用虚构员工数据。

## 本地开发

### 环境要求

- Node.js `22.x`
- Rust stable
- Google Chrome 或 Microsoft Edge

```bash
npm ci
npm run lint
npm run build
npm run tauri dev
```

开发模式允许使用项目根目录下的 `sidecar/` 和系统 Node；发布模式只使用安装包内资源。

## 构建安装包

Windows x64：

```powershell
npm run bundle:windows
```

输出：`src-tauri/target/release/bundle/nsis/测试小助手_0.1.0_x64-setup.exe`

macOS Apple Silicon：

```bash
npm run bundle:macos
```

macOS 包必须在 Apple Silicon Mac 上构建。当前包未签名、未公证，首次打开需要通过 Finder 右键“打开”或在“隐私与安全性”中允许。

完整构建与发布检查见 [BUILDING.md](./BUILDING.md)。

## 常见问题

- **提示未配置 API Key**：登录当前用户后到“系统设置”保存并测试密钥；顶部状态栏也提供“去设置”快捷入口。
- **CDP 连接失败**：先点击“一键启动受控浏览器”，并确认端口未被占用。
- **AI 整理需求返回 502**：应用会直接调用标准 `/v1/chat/completions` 地址，并对 `502/503/504` 自动重试两次；若仍失败，先将推理强度调低后重试，再由网关管理员检查对应模型的上游渠道、权限和超时限制。
- **安装版提示 sidecar 资源缺失**：重新安装应用；发布版不会回退到系统 Node。
- **macOS 无法直接打开**：当前为内部未签名包，按上面的 Gatekeeper 说明操作。
- **构建提示 Node 版本错误**：切换到 Node 22 后重新执行 `npm ci`。
- **本地运行报 `CustomEvent is not defined`**：当前终端仍在使用旧版 Node。确认 `node -v` 为 `22.x` 后重新执行 `npm ci` 和 `npm run tauri dev`。
